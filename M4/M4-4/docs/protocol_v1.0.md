# 4.1
## 字节序约定
采用小端
## 有符号数
负数用二进制补码（按位取反再加1）
##  浮点
角度用int16定点数，放大系数*100，不用float，减少串口输出不稳定（运算慢，资源占用大，输出格式不稳定）。
## CRC参数
CRC-16/MODBUS；多项式为0x8005，反射式0xA001,初始值0xFFFF,反转输出输入。
## CRC覆盖范围
从帧头第一个字节开始，到载荷最后一个字节为止。
## 示例帧
示例1：速度指令帧（上位机 → MCU，左右轮各 68 r/min）

AA 55 04 01 44 00 44 00 D4  BD
│     │  │  └────┬────┘ └──┬─┘
│     │  │       │         └─ CRC16（小端）
│     │  │       └─────────── 载荷: int16 左轮 / int16 右轮（小端）
│     │  └─────────────────── 消息 ID = 0x01（速度指令）
│     └────────────────────── 载荷长度 = 4 字节
└──────────────────────────── 帧头 0xAA 0x55
示例二：状态回报帧（MCU → 上位机，左右轮各 68 r/min，pitch=15.2° 转定点1520，heartbeat=1，bad_frame_cnt=0）

AA 55 0E 02 44 00 44 00 F0 05 01 00 00 00 00 00 00 00 16   D2 
│     │  │  └────┬─────────────────────────────────┘  └──┬─┘
│     │  │       │                                       └─ CRC16（小端）
│     │  │       └─────────── 载荷: int16 左轮 / int16 右轮（小端）/int16 俯仰角/int16 心跳/int16 坏帧计次/int 16 过时计次/ int 16 溢出计次
│     │  └─────────────────── 消息 ID = 0x02（状态回报）
│     └────────────────────── 载荷长度 = 14 字节
└──────────────────────────── 帧头 0xAA 0x55
1.checksum只能检出单字节错误，检测连续的字节会出现漏检，因为是求和，CRC可以检出连续多位、突发噪声，抗干扰强，适合串口噪声环境，因为是每一个字节取余，用余数做校验码。
2.不做转义，依靠状态机+长度字段校验；收到帧头后，按“长度”收够载荷，CRC校验失败直接丢弃，重新回到找帧头状态。
3.代码里加载荷最大上限保护，比如限制最大载荷32B，长度>32直接丢弃，防止缓冲区溢出，找下一个帧头。
